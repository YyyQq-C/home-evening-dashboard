# 安装和第一次打开

如果希望从下载开始跟着做，先看 [新手上手与完整配置示例](00-新手上手与配置示例.md)。本节补充文件位置、YAML 注册和加载排查。

## 先判断你需要哪部分

已有 HA 实体，只想用界面：只处理 `www/home-evening`、`site-config.js` 和仪表盘配置。

设备还没接入：先按设备品牌安装集成。控客用户可参考本包 `konke_local`；其他品牌不用改成控客，只要最终得到可用的 `light`、`switch`、`climate` 或 `fan` 实体即可。

只想用原生界面实控：把 `configs/native-controls.example.yaml` 中的实体替换成自己的实体，在新仪表盘使用。不需要这套 Three.js 模型。

## 文件放在哪里

HA 配置目录是包含 `configuration.yaml` 的目录。HA OS 或容器内常见为 `/config`，作者的 SSH 环境另用配置目录名；用户必须以自己安装方式为准，不能照抄作者机器的绝对路径。

复制后结构应是：

```text
<HA 配置目录>/
  configuration.yaml
  www/
    home-evening/
      index.html
      control.html
      app.js
      control-page.js
      control-actions.js
      site-config.js
      model-host.html
      model.js
      assets/
      optional/
```

对应的浏览器资源路径是 `/local/home-evening/index.html`。不是 `/www/home-evening/`，也不是 Windows 本机磁盘路径。

这些静态资源可以由 HA 提供，不要在其中放凭据、数据库、整个集成目录或自己的 `.storage`。实体 ID、摄像头序列号也会进入客户端；本包默认留空，若自己的分享包要再次公开，先清理这些字段。

## 添加仪表盘：界面方式

1. 在 HA 的“设置 → 仪表盘”创建一个新的可编辑仪表盘，命名为自己能区分的名称。
2. 打开新仪表盘，进入编辑和“原始配置编辑器”。只在这个新仪表盘粘贴 `configs/dashboard.yaml`。
3. 保存后出现“户型展示”和“真实控制”两个页签。
4. 从这两个页签打开页面，而不是把 `/local/...` 地址直接当作独立应用收藏。直接打开静态 HTML 时没有父级 HA 的 `hass` 对象，不能取得当前会话。

页面复用当前用户登录，不新增长期令牌。HA 使用 HTTPS 时，保持同源 `/local/`，不要另外嵌入一个 HTTP 服务器。映射方式依据 [HA Webpage card 文档](https://www.home-assistant.io/dashboards/iframe/)。

## 添加仪表盘：YAML 方式

`configs/configuration-dashboard.example.yaml` 是合并示例，不是一份可以覆盖整个 `configuration.yaml` 的文件。

将 `configs/dashboard.yaml` 复制为 `<HA 配置目录>/home-evening-reader.yaml`，然后把示例中 `home-evening-reader` 这一项合并到现有 `lovelace.dashboards`。已有顶层键时向原结构追加，不重复写两个 `lovelace:`。

由使用 HA CLI 的管理员执行 `ha core check` 检查配置；确实需要加载新的 YAML 注册时，再按安装环境重载或重启。`ha core restart` 会短暂中断 HA，复制静态页面文件本身不要求每次重启。

## 第一次配置

先打开 `site-config.example.js` 看结构，再编辑正在使用的 `site-config.js`。示例里的 `climate.my_living_ac` 等只是占位名，没有对应设备。

基础顺序是：

1. HA“开发者工具 → 状态”复制准确实体 ID，别复制展示名称。
2. 填入 `control.devices`，保持只读。
3. 回到 HA 的“真实控制”页检查状态，空调应能显示当前模式、设定温度等真实字段。
4. 回到原生设备详情，确认该设备在 HA 中确实可控。
5. 修改 `mode` 为 `live` 后，再开始一台设备的验证。

如果暂时只看户型、日历和背景，不填实体也能运行。天气、概览、平板状态会提示未配置或不可用；真实控制按钮保持禁用。户型展示里的设备按钮始终只是本地模拟。

## 更新配置没有生效

确认编辑的是 HA 上正在提供的 `www/home-evening/site-config.js`，不是解压包里另一份文件。浏览器可能缓存 ES module，先重新加载 iframe 或用新的隐私窗口验证；更新入口时也可以在 iframe URL 上改变一个版本参数。仍然显示旧内容时，检查该模块请求的实际返回内容，不要只改 HTML URL 就认定所有依赖已经更新。

如果自己部署了额外 Service Worker，还需要按自己的缓存规则处理。本包不注册 Service Worker，也不改 HA 全局缓存。

## 外观怎么改

背景更换、小时轮换、固定单图与缓存处理见 [更换背景图片](06-更换背景图片.md)。中间户型另见 [更换户型和维护](05-更换户型和维护.md)，不要用换背景的步骤代替户型坐标调整。
