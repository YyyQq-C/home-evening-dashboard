# 背景图片：上传、共享和轮换

本节对应当前新版。原展示页 `index.html` 已支持“显示设置 → 背景图片”；独立家居控制页 `control.html` 仍使用 `control.css` 的纯色布局。

背景与中间户型是两件事。更换整页背景用本节；更换 2D 房屋图片、房间坐标或三维模型，见 [户型教程](05-更换户型和维护.md)。

## 第一次使用：先选择是否安装共享后端

| 用法 | 需要什么 | 保存范围 |
| --- | --- | --- |
| 只用自带背景 | 复制前端即可 | 默认内置背景；无后端时上传和共享规则不可用 |
| 上传图片、固定某张、选择显示方式及轮换规则 | 前端 + `home_evening_backgrounds` 后端 | 保存到自己的 HA，多个设备共用 |
| 不装后端，仅同名替换内置图片 | 自己管理 `assets` 文件 | 静态文件随页面发布，下面有步骤 |

背景后端不创建家电实体、不执行设备控制，但允许所有已登录 HA 账号上传、删除和修改规则。这是当前实现的管理范围，含展示账号；若你需要只允许管理员写入，需要自行调整后端权限校验，不能仅靠隐藏前端按钮隔离权限。

## 安装共享背景组件

1. 备份自己当前的配置和前端。
2. 将仓库 `integrations/custom_components/home_evening_backgrounds` 整个复制到自己的 HA 配置目录下 `custom_components/home_evening_backgrounds`。只复制程序，不复制作者机器的图库和存储。
3. 将 [configs/backgrounds.example.yaml](../configs/backgrounds.example.yaml) 的顶层键合并进自己的 `configuration.yaml`。不要覆盖原文件，已有同名键不重复添加。

```yaml
home_evening_backgrounds:
```

4. 在自己的 HA 管理环境检查配置。具备 HA CLI 的终端可执行 `ha core check`；检查通过后，在合适时机 `ha core restart` 加载这个新组件，重启会短暂中断 HA。其他安装方式使用自己的服务管理方法。这不是仅换静态图片时每次都要执行的步骤。
5. 同步当前完整的 `www/home-evening` 前端，再从同源 HA 仪表盘打开页面。这里不需要长期令牌，组件复用当前登录会话。
6. 展开显示设置，找到背景图片。成功时可以管理图库；失败时检查配置、日志和接口，不要因为默认背景仍能显示就认为后端已加载。

HA 配置目录指包含 `configuration.yaml` 的目录，常见为 `/config`，以自己的安装为准。新组件使用 HA 的 HTTP、存储及现有 Pillow 图片能力；本次未替所有 HA 版本做安装兼容验证。

## 页面上怎么操作

背景区域顶部显示当前图片预览，下面三个分组默认收起：

### 图片与上传

展开后点击“上传背景图片”，可多选 JPG、PNG、WebP，上传前可以选择深浅通用、仅浅色或仅深色。单张不超过 10MB，最多保留 30 张上传图片，原图最多 4000 万像素。

图片保存到 HA 后，点击缩略图即可选用。每张自定义图可以设置适用主题、参与轮换、上移、下移或删除。内置图片不提供删除。

删除影响的是共享图库，不是仅从当前屏幕隐藏；其他设备也会同步。只想暂时不轮到它，可以关闭该图“参与轮换”，不必删除。

### 图片显示方式

| 选项 | 行为 | 适用情况 |
| --- | --- | --- |
| 填满裁剪 `cover` | 保持比例铺满，边缘可能被裁 | 氛围背景，优先画面铺满 |
| 完整显示 `contain` | 保持比例完整显示，可能留边 | 竖图、主体必须完整保留 |
| 拉伸铺满 `stretch` | 使用 `100% 100%` 铺满，可能变形 | 自己确认允许拉伸的图案 |

设计画布是 2000×1200，现有内置图也是这个尺寸，比例为 5:3。上传图不强制裁成这个尺寸；服务端按原比例缩放，显示阶段才按上述规则处理。仍要在目标平板上检查清晰度、裁切和文字对比。

### 自动轮换

- 关闭“循环背景”固定当前选择；没有适用于当前主题的图片时会回退内置图。
- 开启后，来源可以选内置、我的图片或全部图片。
- 顺序轮换按图库顺序；随机轮换为可跨设备复现的洗牌规则，同一主题、同一共享状态及时钟一致时结果一致。
- 间隔支持 5 秒至 24 小时，可用秒、分钟、小时输入。非法间隔会提示，不提交。
- 每张图片能独立排除出轮换，主题归属也参与筛选。改成浅色后看不到仅深色图是正常的。

前端每 5 秒同步共享规则，按约 1 秒的可见轮询更新当前背景；后台页面暂停，恢复可见时同步。因此多个页面之间可能有短暂更新时间差，不能把它当成逐帧同步播放器。

## 图片与规则保存在哪里

| 内容 | 相对 HA 配置目录的位置 |
| --- | --- |
| 图库元数据与规则 | `.storage/home_evening_backgrounds` |
| 上传图片和缩略图 | `home-evening-backgrounds/` |
| 后端程序 | `custom_components/home_evening_backgrounds/` |
| 公开内置图片 | `www/home-evening/assets/background-*.webp` |

上传图会校验、转换为 WebP，最长边缩至 4096px，另生成最长 320×192 范围内的等比缩略图，不保留原始元数据。原始家庭照片不要随仓库再次公开。

上传图片不放到 `/local/`。前端通过已有会话的认证请求取得图片，再生成当前页面的 Blob URL；不把 HA 访问令牌写进 CSS、图库记录或静态文件。

接口为 `GET/POST /api/home_evening/backgrounds`，图片通过受认证的 `/api/home_evening/backgrounds/image/...` 读取。程序使用 revision 检查并发修改，冲突时先同步再提示重新操作，不直接覆盖其他设备的新配置。通常不需要手工调用接口，更不要手改运行中的 `.storage`。

## 不安装后端时，同名替换内置图

先备份原文件，再把自己的纯背景真正导出为 WebP，复制到 HA `www/home-evening/assets/` 下，保持下面的文件名。只改 JPG 的扩展名不会转换格式。

| 主题 | 0 号 | 1 号 | 2 号 |
| --- | --- | --- | --- |
| 深色 | `background-night.webp` | `background-night-aurora.webp` | `background-night-interior.webp` |
| 浅色 | `background-day.webp` | `background-day-interior.webp` | `background-day-lineart.webp` |

默认规则仍是每小时按顺序切换三张，同一小时刷新通常不变。没有后端又想一套主题固定一张，可以把同一张图复制成该组的三个文件名。正常安装共享后端后，优先在页面关闭循环，不需要改源码。

## 从旧版手工背景方案升级

旧版教程通过 `data-ambient` 和 CSS 选择器切图。新版由 `ambient.js` 的图库函数和 `backgrounds.js` 设置当前 CSS 变量，不再让 `settings.js` 两处硬编码的 3 决定共享图库数量。

1. 如果自己在 `screen.css` 末尾加过固定背景的 `--ambient-image: ... !important`，升级时先备份并移除。它会覆盖新版设置，即使上传成功也仍显示旧图。
2. 不要照旧教程仅增加 `data-ambient="3"` 或把两处数字改为 4。现在要扩展上传图库，直接上传即可；修改内置列表属于开发修改，需要同时处理 `ambient.js` 的文件列表、名称和后端内置 ID 校验。
3. 更新前端不会自动清空已存在的共享图库。保留自己的 `.storage` 及独立图片目录；需要整体回退时也分别备份这两部分。

## 常见问题

| 表现 | 检查顺序 |
| --- | --- |
| 有默认图但上传不可用 | 是否安装并加载背景后端；是否从已登录 HA 的同源 iframe 打开 |
| 404 | 组件目录和配置入口；看日志是否加载失败；不要只复制前端 |
| 未认证或权限失败 | 检查当前 HA 会话和用户，不能把令牌放 URL 解决 |
| 上传后没显示 | 当前主题是否适用、图片是否参与轮换、来源选择与固定规则 |
| 设置成功仍是旧背景 | 是否保留旧 `!important` 覆盖；检查实际返回 CSS、JS 与图片缓存 |
| 另一台设备没立刻变 | 等待规则同步；确认同一 HA、当前主题、设备时钟及页面可见性 |
| 图片变暗或有留边 | 主题遮罩和显示方式的结果，按预览检查，不直接删掉背景伪元素 |
| Pad 点击上传无反应 | Android WebView 宿主必须实现文件选择回调，网页不能替它弹系统选择器；升级自己的宿主应用 |
| 冲突提示 | 其他设备先保存了新状态，页面已同步，重新检查后再操作 |

静态同名换图时，可在自己的 HA 地址后打开 `/local/home-evening/assets/background-night.webp?v=bg-2` 核对内容。CSS/模块缓存需分别检查实际返回文件，不能只修改 iframe HTML 的版本参数就认定全部刷新。本项目不注册 Service Worker。

## 本次验证与边界

公开后端的本地测试验证图片格式、大小、尺寸、主题、间隔和路径输入；前端使用本地 HA 替身验证图库操作。没有在本轮同步中安装、重启作者的 HA，也没有公开实际上传图库。真实平板文件选择、图片解码性能、旧 HA 兼容性仍需在自己的环境核对。
