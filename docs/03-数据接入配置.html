天气、电网、摄像头与平板

共通原则

这些配置只负责把已有数据放到展示页。设备还没接入 HA 时，先安装对应集成，确认实体存在。前端配置不包含账号、密码、API 密钥、验证码或长期令牌；本包不会自动登录你的供应商账户。

integrations/custom_components 是可选的后端程序快照，不是必须全部安装的依赖。已有同名集成时先对照版本和备份，避免丢失自己后续修改。复制集成程序后通常需要重启 HA，且首次加载需要 HA 能安装 manifest.json 声明的依赖。本包不是离线 HA 安装包。

天气

用已有天气实体

在 site-config.js 的 entities 中填写：

'weather.example_weather': 'weather.my_home'

替换为 HA 状态页中的准确天气实体。当前温度、状态和预报要由集成实际提供；不支持小时预报的实体不会因为页面订阅而产生小时数据。

sun.sun 使用 HA 自带太阳实体。家庭时区以 HA 配置为准，独立本地预览回退为 Asia/Shanghai。

和风附属传感器

weather.sensors 使用天气字段名到真实传感器的显式映射，不再按名称后缀 _2 自动搜索。以下是示例，保留实际存在的字段即可：

weather: {
  sensors: {
    uv_index: 'sensor.my_weather_uv',
    qlty: 'sensor.my_weather_air_quality',
    pm2_5: 'sensor.my_weather_pm25',
    precip: 'sensor.my_weather_precip',
    ganmao_index: 'sensor.my_weather_cold_index'
  }
}

其中 uv_index、qlty、pm2_5、precip 是当前天气详情直接读取的指标；其他映射会进入附属天气信息分组。qlty 若由上游提供文字类别，就显示文字，不强制转数字。

选择传感器时核对地点、单位和最后更新时间。更换定位后不能把旧地点的空气质量留在新地点的天气卡里。缺失值显示占位，不补成零。

使用随包的预算版 heweather

目录 integrations/custom_components/heweather 是作者环境取出的程序快照，版本清单为 2.4.8，包含 monthly_quota.py 本地改动。上游来源为 c1pher-cn/heweather。账户、位置、JWT 材料和预算账本均不在包中。

第一次安装时，把该组件目录放到自己的 <HA 配置目录>/custom_components/heweather，再通过 HA 的设备与服务配置自己的认证方式、Host 和地点。认证字段按当前和风控制台和组件要求填写；本包不提供公用账号或密钥。

预算版不能直接带着空账本开始请求。它会主动阻止缺少合法初始化数据的请求，并出现 Monthly quota must be initialized with current usage，意思是预算需要使用当前月份的实际已用次数初始化。

初始化顺序：

  1. 查看自己和风控制台中本月的已用请求次数，记录 HA 家庭时区对应的月份。这个数不是作者历史记录，也不是所有人都填零。
  2. 在本包根目录，使用 Python 3 生成一份本地初始化文件。下面命令只生成本地文件，不连接 HA；2026-10 和 123 都是举例，必须换成自己的值。
python tools/make_weather_quota.py --month 2026-10 --used 123 --output my-weather-quota.json
  1. 确认 HA 中 从未初始化过 这个预算。如果已有 <HA 配置目录>/.storage/heweather_monthly_quota，保留原文件，不用本工具重建，不把已有使用量或缓存清零。
  2. 在首次加载预算组件前，由管理员停止 HA Core，再将刚生成的文件复制为 <HA 配置目录>/.storage/heweather_monthly_quota。不要在运行中的 Core 持有账本时覆盖文件。
  3. 按自己的环境检查文件权限并启动 Core，查看预算日志和天气实体。不要把这份包含自己使用量的文件再放回公开 ZIP。

适用于具备 HA CLI 的管理终端：ha core stop / ha core start 会中断和恢复 HA，只有执行初始化、且自己确认路径和现有账本状态后才使用；本包没有替你执行。CLI 环境之外使用自己安装方式对应的服务管理方法。

MONTHLY_LIMIT 在 monthly_quota.py，当前代码为 45,000 次。这是本地预算，不代表和风当前套餐；修改必须结合自己的账号上限。它只管理这套 HA 集成经过预算函数的请求，不能替你统计同一账号在其他程序中的调用。更新上游集成后要重新核对这层本地改动。

电网

后端取数

国家电网账户可参考 integrations/custom_components/state_grid，对应来源 hass-state-grid，快照版本 0.10.0。已有该集成时不必再安装第二份。

先通过 HA 配置流程使用自己的网上国网账户。按实际要求完成新设备验证，确认产生用电量、余额和月度账单实体。南方电网不适用这份集成，其他地区也不能保证返回相同字段。

为电费卡片生成桥接模板

tools/electricity_bridge.py 保留了原项目的数据转换逻辑，家庭户号和实体前缀已替换。打开脚本开头的 ACCOUNTS，填写自己的标识和实体前缀：

ACCOUNTS = {
    'my_home': 'sensor.my_actual_state_grid_prefix'
}

这里的前缀不是随便起名。到 HA 状态页找到真实的每日用电量实体，确认它与其他账单实体的共同前缀，并对照下列后缀逐项核对：

_previous_daily_usage
_current_month_usage
_previous_settled_month_usage
_previous_settled_month_charge
_current_year_usage
_current_year_charge
_account_balance

生成器会拼接这些后缀，并读取 daily_history、monthly_bill_history 等属性。因此它适配的是本包版本的字段合同，不是所有国网或 MQTT 取数方式的通用转换器。如果你用别的集成，要先改模板对应字段。

以下命令在 Windows PowerShell、本包根目录运行，仅把模板 JSON 写到本机，不请求国网、不修改 HA。目标文件已存在时先另存，别覆盖自己的配置。

python tools/electricity_bridge.py | Out-File -Encoding utf8 grid-card.json

把生成文件复制到 <HA 配置目录>/templates/grid-card.json，参考 configs/template-grid.example.yaml 合并一个模板传感器列表。JSON 在这里是有效的 YAML 数据结构，可供 !include 加载。先检查配置，再按自己的模板配置方式重载；原有 template: 内容要保留。

加载后，在 HA 状态页找到刚创建的桥接实体，不要凭显示名推测实体 ID。确认它有 daylist、monthlist、yearlist、预付费、date 等属性，再在前端填写：

'sensor.example_electricity': 'sensor.my_actual_grid_card'

桥接实体填好后，展示页的家中概览会加载包内 optional/smart-utilities-card-ele.js。它不替代后端取数，也不自行登录国网。未配置时显示未配置提示，不重复请求供应商。

用电数据以源数据日期为准；月度账单、年度结算和本月累计不能混用。预付费余额与后付费结算金额不同。缺少的电费不会根据电量强行估算。

摄像头与 SD 回放

只看已有摄像头实时画面

已有正常工作的 camera.xxx 时先在 HA 原生详情播放成功，然后配置：

entities: {
  'camera.example_camera': 'camera.my_home',
  'sensor.example_camera_battery': 'sensor.my_camera_battery'
}

电量传感器没有就留空。播放器通过 camera/stream 申请同源 HLS 地址，不要求在页面写 RTSP 密码。摄像头本身、集成和 HA 流组件必须能够提供浏览器可播放的流。

萤石 BC2 的云端路径

本包的 integrations/custom_components/ezviz_stream 来自作者本地项目代码，清单为 0.3.0，包含中国区相关适配；上游是 rhanekom/hass-ezviz-stream。这不是 BC2 本地 RTSP 接入，也不保证所有中国区账号、机型、固件和未来接口都可用。

这份视频后端源码使用 Python 3.14 语法和较新的 HA 子配置项接口。旧版 HA 不保证能加载，不能只看清单中的 0.3.0 就覆盖旧环境。请先核对自己的 HA/Python 版本；原生已有摄像头的用户完全可以只复用前端，不安装这个后端。

复制组件到自己的 custom_components/ezviz_stream 后，按该版本配置流程添加自己的云账号、地区和摄像头子项。视频通常依赖 FFmpeg，涉及 HA 的媒体流能力；先用原生摄像头或媒体浏览器确认。开启图像加密的设备，验证码在后端对应摄像头子项配置，不写进前端。账号验证不通过时处理实际提示，不修改整个账户的安全设置来碰运气。

作者原环境还使用 ezviz_cn 管理部分设备状态，但它不是这个实时播放入口的强制依赖。本包没有把那个账户配置打包，也没有要求用户安装两个同类账号集成。

本包 SD 卡片

只对本包这一套 ezviz_stream 接口：先在集成选项确认录制媒体暴露和当前摄像头的录像设置，进入 HA 媒体浏览器测试自己的录像。再填：

camera: {serial:'YOUR_CAMERA_SERIAL'}

这里需要的是自己的摄像头序列号，不是设备验证码或账号密码。未填写时 SD 组件不加载，实时画面仍可单独使用。这个值会出现在客户端配置中，分享代码时要再次清理。

卡片文件在 optional/sd-replay-card.js，调用该集成的录像列表和媒体路径，不通用于任意品牌摄像头。列表有条目、解码成功、浏览器真的播放和声音正常是不同检查，按实际情况分别验证。

播放器离开页签会停止；放大只改变当前播放区域，不应该多建立一条流。电池摄像头按需观看，不让页面无意义地全天拉流。

控客底层集成

integrations/custom_components/konke_local 清单为 0.1.0，来自作者的 home-assistant-konke。安装只复制这一层目录，不复制原厂数据库和二进制。

添加集成时填写自己的控客主机地址、端口、SSH 用户、密码及独立核对过的主机公钥。主机公钥不是登录密码；不要通过关闭校验解决不匹配。HA 必须能直接访问该 SSH 入口，集成本身不负责你的异地跳板和子网路由。

读取原厂 SQLite 缓存、SSH 转发和本地协议调用都有型号与固件约束。验证范围是 KK-CC-G12W，离线通道保留但不可控制，没有子设备配置的地址不创建实体。温控和风扇实体出来后，再按《真实控制配置》绑定，而不是把编号当房间名。

平板和其他家电

entities 里 sensor.example_pad_... 等别名用于已有平板 MQTT 实体，不会替你安装 Android App、配置 MQTT 或创建这些实体。没有设备上报时，平板信息显示不可用。

appliance-data.js 中的别名提供家电只读详情。映射索引列出了各字段，没有的保留空值。原展示页暂停、出水、冰箱设置等仍是模拟，新增真实控制入口也没有泛化实现这些家电专有功能；不能把它们误填到灯或新风配置中。
