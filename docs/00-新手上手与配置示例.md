# 新手上手与配置示例

这份流程从“已经有 Home Assistant，但还没部署这个项目”开始。不先装全部集成，不先改三维，先让默认页面正常显示，再接一台自己的设备。

## 开始前准备

| 需要什么 | 用途 |
| --- | --- |
| 已能正常登录的 HA | 提供页面宿主、已有实体与服务 |
| 能管理 HA 配置目录的文件工具 | 复制前端、编辑自己的配置；使用自己已有的文件编辑或文件共享方式 |
| 本项目 ZIP 或 Git 工作副本 | 提供 `www/home-evening` 和配置例子 |
| 一台已接入 HA 的设备（可稍后准备） | 核对实体和实际控制；没有设备也可先看页面 |

仅运行现成前端不需要 npm。设备尚未接入 HA 时，先看页面也没关系，但自定义界面不会替你完成品牌账号登录或网关配网。

## 第一步：下载并找到真正的运行目录

项目地址：

- [GitHub](https://github.com/YyyQq-C/home-evening-dashboard)
- [Gitee](https://gitee.com/YongQianc/home-evening-dashboard)

下载 ZIP，解压后进入包含 `README.md` 的那一层，再找 `www/home-evening`。某些压缩包外面有一层仓库名，不要把这个外层目录误复制成 HA 的 `www`。

文件全部解压后，应能看到 `index.html`、`screen.css`、`site-config.js` 和 `assets`，不要只下载单独一个 HTML。

## 第二步：复制到 HA

找到包含 `configuration.yaml` 的 HA 配置目录，将前端放成：

```text
HA 配置目录/www/home-evening/index.html
HA 配置目录/www/home-evening/control.html
HA 配置目录/www/home-evening/site-config.js
HA 配置目录/www/home-evening/assets/...
```

HA OS/容器内常见配置目录为 `/config`；文件共享和 SSH 所见路径可能不同，以自己的环境为准。没有 `www` 时可新建；已存在同名项目目录则先备份，避免覆盖自己的配置。

在浏览器用当前 HA 地址加上以下路径检查一个背景文件：

```text
/local/home-evening/assets/background-night.webp
```

能看到背景图，说明基本静态路径可用。404 时先检查目录有没有多套一层、文件名大小写是否一致。看到图片还不等于页面已获得 HA 会话。

## 第三步：添加新仪表盘

1. 在 HA“设置 → 仪表盘”新建可编辑仪表盘。
2. 进入新仪表盘的编辑和原始配置编辑器。
3. 复制 [configs/dashboard.yaml](../configs/dashboard.yaml) 的全部内容到这里，保存。
4. 打开“户型展示”，应看到默认户型、时钟、背景。
5. 打开日历，应能查看月份；打开“真实控制”，应看到只读提示。

页面左侧导航在边缘收起，展开以后可以找到显示设置，切换主题、2D/3D 和屏保参数。显示偏好保存在当前浏览器，另一台平板需要单独设置。

没有配实体时，天气、概览等显示未配置或不可用是预期结果。直接打开静态 HTML 或本机预览地址没有 HA 父级会话，设备连接状态不能与仪表盘内的结果混为一谈。

不想通过界面注册仪表盘时，可使用 [YAML 方式](01-安装和第一次打开.md)。静态资源复制不要求重启；只有实际修改了需要加载的 HA 配置，才按安装环境检查并重载。

## 第四步：找自己的实体 ID 和能力

在 HA“开发者工具 → 状态”搜索设备名称，点击结果，复制类似 `climate.my_living_ac` 的实体 ID。名称可以重复，ID 才是配置目标。

| 实体类型 | 示例（不是实际设备） | 应核对的字段 |
| --- | --- | --- |
| 灯 | `light.my_living_light` | 状态、是否支持调光 |
| 继电器灯 | `switch.my_living_light` | 仅开关，不会有灯光亮度 |
| 空调 | `climate.my_living_ac` | `hvac_modes`、`fan_modes`、`min_temp`、`max_temp`、`target_temp_step` |
| 地暖 | `climate.my_living_floor` | 支持的 `heat/off`、温度范围和步长 |
| 新风 | `fan.my_fresh_air` | 是否提供 `percentage`、`preset_modes` |

先在 HA 原生详情卡片确认实体正常，再接这张页面。`unknown`、`unavailable`、缺失实体或无权限，都不能通过修改前端显示名解决。

## 第五步：完整配置例子，先只读

先备份自己的 `site-config.js`。下面是一份最小完整结构，适合第一次试用；所有 `my_...` 都要改成自己已有实体，没有的设备删除整项。

```js
/** 项目配置：只放实体映射，不放密码、Token 或 API 密钥。 */
export const SITE = {
  control: {
    mode: 'read-only',
    timeoutMs: 15000,
    devices: [
      {key:'living_light', name:'客厅灯光',
       kind:'light', entity:'light.my_living_light'},
      {key:'living_ac', name:'客厅空调', kind:'climate',
       entity:'climate.my_living_ac', onMode:'cool'},
      {key:'living_floor', name:'客厅地暖', kind:'climate',
       entity:'climate.my_living_floor', onMode:'heat'},
      {key:'fresh', name:'全屋新风',
       kind:'fan', entity:'fan.my_fresh_air'}
    ],
    scenes: []
  },
  camera: {serial:''},
  weather: {sensors:{}},
  entities: {
    'climate.example_ac_living': 'climate.my_living_ac',
    'climate.example_floor_living': 'climate.my_living_floor'
  }
};

/** 供原展示页按照别名读取显式配置的实体。 */
export function entityId(alias) {
  return SITE.entities[alias] || '';
}
```

如果已经配过天气、电费或其他房间，不要整份覆盖，合并示例中的相应字段即可。保留 `SITE` 和 `entityId` 两个导出。

`onMode:'cool'` 只在设备支持制冷、且你需要制冷开机时使用；需要制热则核对 `heat`。这些是明确配置，不由页面按季节猜测。

两组绑定用途不同：

| 配置字段 | 作用 |
| --- | --- |
| `control.devices` | 独立实控页的设备列表、目标和动作类型 |
| `entities` | 原展示页的只读数据别名，不把其模拟按钮自动改成实控 |
| `weather.sensors` | 天气详情的附属传感器 |
| `camera.serial` | 需要特定 SD 回放卡片时的序列号，不是密码或验证码 |

保存后，从 HA 重新加载控制页。浏览器可能缓存模块，实际更新文件和缓存排查见 [安装说明](01-安装和第一次打开.md)。只读状态下应能读到在线实体，操作按钮禁用。

## 第六步：需要真实控制时再启用

1. 原生 HA 中确认设备可控，自己能观察设备。
2. 将 `control.mode` 从 `read-only` 改为 `live`，刷新，确认页面提示真实控制已启用。
3. 先操作一台设备、一个动作，核对服务提示、实体回读、物理设备三项。
4. 设备失联、超时或结果未知时先查状态，不连续重复提交。
5. 测试后不需要实控时，可改回只读。

“HA 已受理”不代表空调已经完成制冷或设备一定执行成功。范围、步长、能力不完整时会拒绝相应动作，详细规则见 [真实控制配置](02-真实控制配置.md)。

## 第七步：换背景，再加其他数据

只换背景不必改户型坐标。按 [背景教程](06-更换背景图片.md) 替换六张主题图，或固定单图；不要误替换 `floorplan-textured.webp`。

天气、电网、摄像头每加一类，先确认其 HA 原生实体，再配到前端。完整后端、桥接和预算步骤见 [数据接入](03-数据接入配置.md)。已有对应集成不必重复安装。

## 完成后检查

| 阶段 | 预期结果 |
| --- | --- |
| 静态文件 | 能打开 `/local/.../assets/background-night.webp` |
| 仪表盘 | 有展示、控制两个页签；无配置也能打开日历 |
| 只读设备 | 在线实体显示实际读数，不能下发 |
| 自己的背景 | 深浅主题和轮换图与预期一致 |
| 实控（可选） | 一次明确目标的动作，有受理、回读与物理观察 |
| 分享文件前 | 清理自己的实体、序列号、位置、账号和日志 |

新手容易出错的通常是目录多了一层、编辑错副本、把展示名当实体 ID、绕过 HA iframe、只换轮换中的一张或遇到缓存。先按这些位置查，再看各专题文档，不用一上来重装所有集成。
