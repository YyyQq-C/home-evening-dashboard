# Pad 操作与本轮界面更新

同步日期：2026 年 10 月 23 日。此次把本地暮色页面已完成的界面优化迁入公开项目，家庭实体仍为空映射，家居独立控制页保留，Pad 控制另有自己的开关。

## 更新了哪些地方

| 部分 | 本轮变化 |
| --- | --- |
| 2D 房间动画 | 房屋、卡片、工具栏使用 transform 平移；灯光蒙版缓存位图，失败保留 SVG 回退，快速反向从当前位置衔接 |
| 页签和侧栏 | 页签改为上下过渡；展开侧栏可上下滑动切页，首尾不循环；侧栏开合有平滑动画 |
| 家中概览 | 摄像头与电费布局收紧并等高，去掉冗余标题；切页期间延后重组件，返回复用卡片 |
| 电网 | 默认用电日历，详情区域固定高度，日月曲线减少相同数据重画；本月电量按已上报日记录累加，电费可独立待更新 |
| 视频 | 实时及录像支持 1～4 倍缩放、拖动、加减与复位；SD 回放在大弹窗显示，离开或关闭停止播放 |
| 主题和家电 | 深浅主题的侧栏、卡片、按钮、弹窗统一；双列管线机按内容撑高，三列长型号允许完整换行 |
| Pad | 详情顶部显示电量、内存、CPU、电池温度；六个操作分组默认收起，提供 23 项可配置操作 |
| 背景 | 图片上传到 HA 共享，支持图库、主题归属、显示方式和轮换规则，详见 [背景教程](06-更换背景图片.md) |

这些优化减少页面重建和重复绘制，不等于所有平板保证稳定帧率。本次公开配置的验证使用本地浏览器和测试替身，没有重新连接实际 Pad 或摄像头。

## 三类操作要分别配置

1. 原户型、家电和场景：继续本地模拟；绑定的读数可以真实。
2. `control.html` 家居实控：由 `SITE.control` 管理，默认 `read-only`。
3. 原展示页中的 Pad 详情操作：由 `SITE.pad` 管理，也默认 `read-only`。

启用家居实控不会连带启用 Pad，反过来也一样。背景上传、删除和规则保存则属于共享图库管理，不是设备控制；启用背景后端后，所有已登录账号均可管理。

## Pad 实体从哪里来

需要自己的 HA Kiosk/MQTT 集成已经在 HA 创建对应的 `button`、`number`、`switch`、`text` 实体。这个项目不会自动创建它们，也不按名称猜测目标。Android 应用可参考 [ha-kiosk-browser](https://github.com/YyyQq-C/ha-kiosk-browser)，本仓库不包含其 APK 或签名文件。

先在 HA“开发者工具 → 状态”及原生实体详情确认每项 ID、范围和可控性。前端的单位与操作类型是适配该类实体的约定，不代表任意同名实体都兼容。

## 配置键与类型

| 分组 | `key` | 实体类型 | 操作或取值 |
| --- | --- | --- | --- |
| 快捷操作 | `reload` / `home` / `wake` / `screenOff` / `screenshot` | `button` | 立即刷新、首页、唤醒、熄屏、截图，`button.press` |
| 屏幕与音量 | `brightness` | `number` | 观看亮度 1～100 |
| 屏幕与音量 | `volume` / `standbyBrightness` | `number` | 音量、待机亮度 0～100 |
| 屏幕与音量 | `dimDelay` | `number` | 无人后降亮度秒数 0～86400 |
| 屏幕与音量 | `motion` / `lock` | `switch` | 人体检测、锁定 |
| 自动亮度 | `schedule` | `switch` | 按时间切亮度 |
| 自动亮度 | `day` / `night` | `number` | 日夜亮度 1～100 |
| 定时刷新 | `daily` | `switch` | 每日刷新 |
| 定时刷新 | `dailyHour` / `dailyMinute` | `number` | 小时 0～23、分钟 0～59 |
| 定时刷新 | `watchdog` | `number` | 页面看门狗 0～3600 秒 |
| 夜间熄屏 | `sleep` | `switch` | 夜间熄屏开关 |
| 夜间熄屏 | `sleepStart` / `sleepEnd` | `number` | 起止小时 0～23 |
| 通知与语音 | `notify` / `speak` | `text` | 画面通知、语音内容，1～200 字 |

以实际 `pad-controls.js` 的操作键为准。默认实体全空，不支持的项可以保留空串，界面会禁用。后端实体上下限比表中更严格时，使用两者交集。

## 最小配置例子

在现有 `SITE` 对象中增加或修改 `pad`，不要删除天气或家居控制配置。以下 ID 都是示例，要换成自己的实体：

```js
pad: {
  mode: 'read-only',
  entities: {
    reload: 'button.my_pad_reload',
    brightness: 'number.my_pad_brightness',
    volume: 'number.my_pad_volume',
    notify: 'text.my_pad_notice'
  }
}
```

全部 23 个键见 `site-config.example.js`。修改后重新加载 iframe，让模块重新读取映射；首次先只读核对。需要提交时才把 `pad.mode` 改为 `live`。只有 `live` 才能构造 Pad 服务命令，缺失、离线或域不匹配的实体不可用。

Pad 是否在线还依赖 `entities` 中配置的 Pad 读数。至少需要正确映射电量、内存或屏幕状态中的可用字段；具体别名见 [实体映射索引](实体映射索引.md)，例如 `sensor.example_pad_dian_liang`。仅填控制 ID、完全没有状态来源时，页面仍可能按离线处理。

## 提交与状态回读

- 按钮和开关点击即提交；数值与文本修改只保留草稿，点击“应用／发送”才提交。
- 数值必须为合法整数；空字符串不会当成 0，零音量等合法值会保留。
- 刷新状态不覆盖未提交草稿，重新打开详情分组默认收起。
- 服务成功仅显示已提交；数值、开关继续等待设备报告，不能把请求成功当作物理执行成功。
- 原本从未按过的按钮和从未发送的文本，HA 状态可能为 `unknown`；这两类与普通不可用传感器分别处理。
- 熄屏、锁定和音量等操作应在自己可观察设备时验证，不用真实动作测试单纯样式。

## 摄像头与手势说明

视频缩放只放大浏览器中的当前画面，不控制镜头光学变焦或 PTZ，也不改变录像文件。双指捏合与加减按钮支持 1～4 倍，放大后可拖动，复位恢复完整画面。

SD 播放仍依赖原有认证、列表和取流能力。大弹窗及样本视频测试通过，不代表任何机型、任何 SD 录像都能播放。先确认原生 HA 媒体能力，再配置序列号。

侧栏滑动只从侧栏开始，不接管天气、日历和详情正文的滚动；短滑、横向拖动、多指和取消不切页，减少动画设置下直接切换。

## 从上一版升级

1. 备份自己的整个前端、`site-config.js` 和仪表盘。
2. 替换本轮前端时，包含新增的 `backgrounds.js`、`camera-zoom.js`、`sidebar-swipe.js`、`pad-controls.js`，不能只复制 `app.js`。
3. 合并 `SITE.pad`，保留已有实体；家居和 Pad 都先只读。没有 Pad 的用户留空即可。
4. 需要共享图库时，另外安装背景后端；仅更新静态页面不能获得上传接口。
5. 保留 HA 中已有 `.storage/home_evening_backgrounds` 和 `home-evening-backgrounds/`，不要把默认配置当成重置工具。
6. 按 [安装说明](01-安装和第一次打开.md) 检查实际返回资源及缓存，再检查桌面、平板和实际设备。

当前公开项目仍不带家庭序列号、图库记录、媒体、数据库或登录凭据，也不附带作者的 SSH 自动部署脚本。
