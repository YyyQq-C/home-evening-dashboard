# 暮色居家 · Home Evening Dashboard

这是一个 Home Assistant 家居仪表盘项目，包含 2D/3D 户型展示、天气、日历、设备状态，以及可显式启用的设备控制入口。仓库同时提供模型源码、集成程序快照和配置示例。没有家庭账号、密码、Token、设备验证码、实际设备 ID、地址、原始 DWG、数据库、配置项或预算账本。不要把解压后的整个目录扔进 HA。

快速开始：先复制 `www/home-evening`，配置实体，添加新仪表盘。后端集成只按你实际缺少的部分安装。

有两个独立入口，使用前请分清：

| 入口 | 用途 | 是否真实控制 |
| --- | --- | --- |
| `/local/home-evening/index.html` | 原暮色界面的 2D/3D、天气、日历、概览、家电展示 | 灯光、设备和场景按钮仍为本地模拟；绑定的读数可以是真实数据 |
| `/local/home-evening/control.html` | 本次新增的配置式设备控制入口 | 默认只读；`control.mode` 显式改为 `live` 后才调用绑定实体的 HA 服务 |

没有把原模型按钮偷偷改成实控。本包的真实控制入口是一张独立页面；如果要让原模型、房间弹窗和场景按钮全部真实联动，还需要按《真实控制配置》最后一节改造原动作入口，并做单独回归。

## 最短安装流程

1. 确认自己的设备已经接入 HA，原生卡片能正常显示和操作。
2. 把本包 `www/home-evening/` 整个目录复制到 自己的 HA 配置目录下的 `www/home-evening/`。不要复制 `integrations`、`model-source`、`tests` 和文档到 `www`。
3. 编辑复制过去的 `site-config.js`。先保持 `control.mode: 'read-only'`，将 `control.devices[].entity` 改成自己的实体。空调、地暖的 `onMode` 由你根据实际支持模式填写；没有的设备从数组删除即可。
4. 新建一个仪表盘，在原始配置编辑器粘贴 `configs/dashboard.yaml`。这里的两个 iframe URL 都是相对当前 HA 的 `/local/` 地址。
5. 从 HA 仪表盘打开“真实控制”页，确认连接、设备名称、状态、支持模式和温度范围。
6. 需要实控时，修改 `control.mode` 为 `live`，刷新这个 iframe；首次只验证一台自己可观察的设备。

不要把 HA 密码、长期令牌、萤石验证码、和风密钥填进 `site-config.js`。页面复用当前登录用户的 HA 会话，集成凭据在 HA 后端配置。

## 本机预览和离线测试

Windows PowerShell、Linux 或 macOS 终端，在本包根目录运行。以下两个命令只操作本机文件或内存，不部署、不连接家电：

```sh
python -m http.server 8793 --bind 127.0.0.1 --directory www
node --test tests/control-actions.test.mjs
```

第一个命令提供本机 HTTP 预览，打开 `http://127.0.0.1:8793/home-evening/index.html`，用 Ctrl+C 停止。该地址没有 HA 宿主，因此天气、设备和真实控制提示未连接是正常现象。它不是交付给平板的运行地址。

第二个命令只运行服务调用白名单、实体隔离、参数范围、只读、重复下发、超时及异常脱敏测试，不要求安装 npm 依赖，不访问 HA。

完整包检查还可以运行 `python tools/validate_package.py`。它需要 Python 3.14 和 Node.js，原因是随包视频后端使用了 Python 3.14 语法；该命令只解析源码，不启动 HA。预算文件与桥接工具不需要加载视频后端。

## 验证范围

本包的真实控制适配通过离线 HA 替身测试和本地浏览器交互检查，未部署到作者的 HA，也没有执行真实家电动作。集成目录是来源版本的程序快照，未在用户的新安装环境执行整套安装、迁移、播放和物理效果验证。前端使用同源 HA 外壳的 `home-assistant.hass`；这是版本相关的前端对接点，不是独立登录客户端。

已有同名集成的用户，应先备份和对照版本，不要直接把快照覆盖到运行中的配置。文档详细区分了必选前端和可选后端，最小运行不要求安装这里的全部集成。
